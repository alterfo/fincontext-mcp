# FinContext MCP — open-core, self-hosted финансовый MCP-сервер для РФ SMB

## Context

Соло-разработчик (JS) хочет монетизируемый pet-проект на serverless (Yandex Cloud Functions + YDB). Путь решений (все зафиксированы через уточняющие вопросы):
1. Разведка рынка → **отказ от селлерских инструментов WB/Ozon**: нишу «AI-автоответы на отзывы» в феврале 2026 нативно съел сам Wildberries + рой бесплатных сервисов → соло там рва нет. Урок: на хайповых рынках против соло стоят и площадка, и венчур, и бесплатные тулы.
2. Пивот **«оттолкнуться от преимущества»**. Преимущество: AI-агенты/MCP + JS + DevOps + кросс-доменный опыт (FinTech/GovTech/EdTech/PropTech/HRTech) + доступ к dev-сообществу.
3. Якорь-вертикаль → **FinTech**.
4. Ключевое ограничение: резидент РФ **без доступа к Stripe/PayPal** → деньги через YooKassa (РФ).
5. Возражение о доверии (никто не отдаст соло токены к банкам) → решено **архитектурно**: модель **self-hosted / open-core** — токены живут у клиента, к разработчику не уходят.

## Итог разведки (обоснование ниши)

- **Боль системная:** кассовые разрывы — массовая проблема 2026, ~27% компаний/ИП столкнулись впервые. Деньги размазаны по нескольким банкам + учётным системам, ручная сверка выписок болит.
- **MCP-в-финансах — топ-кейс мира 2026:** официальные MCP-серверы у QuickBooks (Intuit×Anthropic), Xero, Zoho Books; Goldman посадил Claude на сверку. Направление подтверждено.
- **Зазор:** СберБизнес MCP — единственный корпоративный MCP в РФ, но это стена одного вендора (только клиенты Сбера, только его операции). **Нейтрального кросс-банковского + учётного MCP нет** — ни у Сбера, ни у западных (не знают 1С/Контур/Точку).
- **Кубики для соло есть:** Точка Банк — бесплатный public API; МойСклад — открытый API + импорт выписок из Сбера/Альфы/Точки/Модуля/Т-банка; интеграции 1С/Контур.
- **Ров для соло:** нейтральность + покрытие 1С/Контур/Точки + FinTech-глубина (сверка, ИП/УСН/НДС, банковские причуды) + дистрибуция через dev-сообщество. Платформа не съест — кросс-вендорную агрегацию ни один вендор не строит.

## Продукт и модель (open-core, self-hosted)

**FinContext MCP** — нейтральный MCP-сервер, дающий AI-агенту сводный финансовый контекст SMB по всем банкам и учётной системе. Tools:
- `get_cash_position` — реальный кэш по всем счетам;
- `check_payment` — прошёл платёж или висит;
- `cashgap_forecast` — прогноз кассового разрыва;
- `reconcile` — сверка выписка↔учёт (частичные оплаты, отсутствующие назначения, разные форматы).

**Модель доверия/монетизации:**
- **Клиент разворачивает MCP у себя** — токены банков/учёта лежат в *его* Lockbox/env, к разработчику не уходят. Доступ к банкам — **только read-only scope**.
- **Open-core:** открытое ядро (протокол MCP + базовые коннекторы Точка/МойСклад) = аудируемость → доверие через прозрачность, а не бренд. **Закрыто/по лицензии:** движок сверки (`reconcile`), прогноз разрыва, premium-коннекторы (1С/Контур/др. банки), алерты.
- **Целевой покупатель — билдеры/интеграторы** финансовых агентов (аудитория пользователя; взрывной наём Сбер/Яндекс/МТС/X5). Они self-host'ят коннектор → разработчик не видит данные в принципе.
- **Заработок (YooKassa, РФ):** Pro-лицензия (ключ разблокирует premium-модули) + платная поддержка/внедрение + опциональный managed-хостинг позже, для тех, кто уже доверяет.

## Роль Yandex FaaS

- **Основной артефакт деплоя — Terraform-модуль**, который разворачивает MCP в **облако клиента (его Yandex Cloud): Functions + API Gateway + YDB + Lockbox**. Serverless = дёшево, без ops — сильный аргумент для self-host.
- **Твой демо-инстанс** на собственном FaaS — для маркетинга/песочницы (на демо-данных, без чужих токенов). Так FaaS-навык прокачивается на обеих сторонах.

## Архитектура

- `functions/mcp/index.js` — HTTP-функция за API Gateway, MCP по streamable-HTTP (JSON-RPC): `initialize`, `tools/list`, вызовы tools.
- `functions/sync/index.js` — timer-триггер: тянет свежие выписки/оплаты в кеш (YDB), пересчитывает кэш-позицию/прогноз.
- `src/mcp.js` — регистрация tools и роутинг JSON-RPC.
- `src/reconcile.js` — **доменное ядро** (сверка/кэш-позиция/прогноз) — главный носитель рва; premium.
- `src/connectors/{tochka,moysklad,kontur,1c}.js` — адаптеры + нормализация выписок в единую модель (tochka/moysklad — open; kontur/1c — premium).
- `src/ydb.js`, `src/lockbox.js` — инфраструктура (читают токены из Lockbox *клиента*).
- `src/license.js` — проверка Pro-ключа (офлайн-валидация подписи, без телеметрии — важно для доверия).
- `infra/` — Terraform (провайдер `yandex`): функции, API Gateway (OpenAPI), timer-триггер, YDB, Lockbox, сервис-аккаунт с минимальными правами. Это и есть поставляемый клиенту деплой.
- `README`/`docs/` — прозрачная модель безопасности (что хранится, что НЕ уходит наружу), инструкция подключения MCP-клиента.

## Как разрабатывать и тестировать (свой бизнес НЕ нужен)

Слоёный цикл разработки; для старта не требуется ни SMB, ни реальные деньги, ни чужие токены:

1. **Доменное ядро на синтетике (0 доступов).** `src/reconcile.js` и прогноз — чистые функции. Генеришь синтетические выписки+проводки с заранее известными расхождениями → Jest. Это большая часть ценности/рва, тестируется полностью локально.
2. **Точка — песочница «из коробки» (0 регистраций).** URL → `https://enter.tochka.com/sandbox/v2`, `Authorization: Bearer sandbox.jwt.token` (все права, тестовые данные, прод не трогается). Коннектор Точки пишешь/тестируешь без реального счёта.
3. **МойСклад — бесплатный тестовый аккаунт.** JSON API бесплатен на всех тарифах; отдельной песочницы нет — регистрируешь бесплатный тестовый аккаунт и сам наполняешь тестовыми товарами/оплатами.
4. **MCP Inspector — локальный драйв сервера.** `npx @modelcontextprotocol/inspector` (web/CLI/TUI, streamable-HTTP) → вызываешь `tools/list`, `get_cash_position`, `reconcile` без деплоя; CLI-режим = автотесты в CI.
5. **FaaS-интеграция.** Логика в `src/` (эмулятора YC нет) → деплой dev-версии функции → вызов через API Gateway → Cloud Logging. Terraform-модуль проверяешь развёртыванием в чистый YC-каталог.
6. **Реальные данные — потом и опционально.** Для живого e2e открой самозанятость/ИП (нужно всё равно для YooKassa) + счёт в Точке + бесплатный МойСклад → станешь **своим первым клиентом** (dogfooding), затем design-partner из dev-сообщества.

Ключ: пункты 1–4 не требуют ни бизнеса, ни реальных денег, ни чужих токенов.

## Порядок работ

1. **Валидация до кода:** пост в dev-сообществе/на Habr про идею open-core финансового MCP + 5–10 интервью с теми, кто строит финансовых агентов. Цель — подтвердить готовность платить за Pro/поддержку и приоритет premium-коннекторов.
2. Каркас: Terraform + `functions/mcp`, отвечающий на `initialize`/`tools/list` через API Gateway.
3. **Открытое ядро:** коннектор **Точка** — сначала на песочнице (`/sandbox/v2`), затем read-only prod → `get_cash_position`, кеш в YDB. Публикация в GitHub + MCP-реестрах/директориях.
4. **МойСклад** (бесплатный тестовый аккаунт) → включить `reconcile` (ядро ценности; premium).
5. `cashgap_forecast` + timer-sync + алерты (premium) + `src/license.js` (гейт premium по Pro-ключу).
6. YooKassa: продажа Pro-ключа (это продажа софта/лицензии, не сервиса-хранилища — юридически проще).
7. Пилот на 3–5 билдерах/бизнесах из списка валидации; сбор кейсов для дистрибуции.

## Проверка (end-to-end)

- Юнит-тесты `src/reconcile.js` и коннекторов (Jest) локально — эмулятора YC нет, доменная логика отделена от handler'ов.
- E2E MCP: подключить локальный MCP-клиент (Claude Desktop / MCP-инспектор) к своему демо-инстансу → `get_cash_position` и `reconcile` на демо-данных → сверить с ручным расчётом.
- Проверка Terraform-деплоя: развернуть модуль в чистый YC-каталог, убедиться, что MCP поднимается и читает токены из Lockbox этого каталога.
- Проверка лицензии: без Pro-ключа premium-tools недоступны; с валидным ключом — открываются (офлайн, без обращения к твоим серверам).
- Проверка sync/дедупа: повторный проход не задваивает транзакции.
- Логи в Cloud Logging (`yc logging read`).

## Риски / открытые вопросы

- **Монетизация open-core:** держать премиум-ценность (движок сверки, прогноз, 1С/Контур, алерты) достаточно весомой, чтобы за Pro платили; открытое ядро — «на попробовать» и для доверия. Доп. канал — платное внедрение/поддержка.
- **«Платят ли за open source»:** да — за premium-модули, поддержку и managed-хостинг; плюс бизнес платит за деплой+сопровождение. MRR умеренный, но реальный — ок для pet-проекта.
- **Хрупкость API** банков/учёта — изолировать в `connectors/*`, версионировать, мониторить.
- **Юр. аспект приёма оплаты:** оформить самозанятость/ИП для YooKassa; продажа лицензии проще, чем обработка чужих финданных (её ты избегаешь by design).
- **Стартовое покрытие:** только Точка + МойСклад; расширять по спросу, не пытаться покрыть все банки сразу.
- **Лицензионная модель open-core:** выбрать лицензию (напр. открытое ядро под пермиссивной, premium-модули — проприетарные/по коммерческой лицензии).
